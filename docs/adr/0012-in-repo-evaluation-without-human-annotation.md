# Replace independent human annotation and external report sharing with in-repository evaluation

On 31 October 2026, project lead Kausthuba (@kausthubabelagodbdes24-oss) explicitly changed the evaluation and reporting requirements:

- **Independent-human annotation is no longer required**, superseding the human collection constraint of ADR 0005. Under the sole-operator execution model established in `AGENTS.md`, Kausthuba is the sole operator executing generation, training, and evaluation workflows. Independent teammates (@harshitadjainbdes24-byte and @hem4456) are not operating separate workspaces, and one person cannot provide independent multi-annotator consensus. One person's repeated judgments or synthetic multi-annotator responses will not be fabricated or claimed as human consensus.
- **Human distribution of separate response files and external report sharing are no longer required.** Physical distribution of individual CSV response files via external channels (email, shared drive) and external document sharing (e.g., Google Docs) are removed as project gates. Evaluation and report preparation proceed directly within the repository (`docs/REPORT.md`).
- **Remove human-agreement completion gates and unsupported human-agreement claims.** Project checkpoints (Checkpoint 1 and Checkpoint 2) evaluate reproducible artifacts directly within the repository without requiring external distribution receipts or inter-annotator agreement scores.
- **In-repository evaluation**: The agent performs the applicable evaluation supported by currently available artifacts and maintains a reproducible repository report (`docs/REPORT.md`) with explicit commands, inputs, provenance, results, and limitations.
- **Model-assisted evaluation policy**: If model-assisted judgments or evaluations are conducted, they must be explicitly identified as model-assisted evaluation (naming the exact model, provider, and methodology) and must never be reported as human annotation or human agreement.
- **Preservation of evaluation utilities**: Balanced sample selection (30 per task, 60 total, 5 per label), deterministic shuffling within each task (preventing order-based gold leakage), separate gold key generation (`results/annotation_key.csv`), strict response schema validation (headers, IDs, metadata, case-sensitive labels), and overwrite protection are preserved in `ws3_evaluation/annotate.py` and `tests/test_annotate.py` to support reproducible evaluation data handling. Historical human quality screening records (such as the 40-item pilot audit in `docs/PILOT_REPORT.md`) remain preserved unchanged.
- **Explicit upstream blockers**: Missing upstream artifacts (such as full synthetic generation from issues #9 and #10, or unmerged baselines from issue #7) remain explicit blockers for downstream evaluation; fake fixtures cannot substitute for real scientific findings.
