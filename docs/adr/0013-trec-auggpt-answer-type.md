The approval answers the PR #29 lead review (`pullrequestreview-5722864116`), which found that the earlier version of this record cited approval without trusted evidence. The approval text, verbatim:

> I explicitly approve the TREC seed-13 AugGPT prompt correction described in ADR 0013 (`auggpt-trec-answer-type-v1`): regenerate all 360 paraphrases from the unchanged 60 sources, preserve answer type and source meaning, carry forward no old rows, and leave Emotion, zero/few-shot artifacts and results unchanged. This approval authorizes the code change only; it does not authorize generation, promotion, freeze, training, or merging.

## Context

The #11 round-1 model-assisted review (PR #28) flagged `trec/auggpt_seed13`: 2 clear errors among 10 sampled rows, both changing the TREC expected answer type, i.e. the label (`trec.train.04257.seed13.aug5` abbreviation → definition request; `trec.train.00845.seed13.aug3` description → "which event"). The lead's PR #28 review confirmed both. ADR 0008/0009/0012 require investigation, correction and a fresh recorded random review. The likely cause is that `prompt_auggpt` asks only to keep the meaning and does not mention the question's answer type.

## Decision

- **Scope:** TREC only, seed 13 only. Regenerate all 360 paraphrases (six for each of the 60 unchanged canonical `trec/lowres_seed13` sources). Emotion, zero/few-shot corpora, real sources and existing results are unchanged. Other TREC repetitions are historical and keep the old prompt.
- **Prompt** `auggpt-trec-answer-type-v1` (`ws1_generation.generate.prompt_auggpt_trec_answer_type`, routed by `auggpt_prompt_for`) replaces `prompt_auggpt` and the length guard for every TREC seed-13 source. It gives the source's canonical label and its `config.yaml` definition and requires every rephrasing to keep the expected answer type and label, the facts and their relationships, entities and participants, negation and intent. Abbreviation questions must still ask what the abbreviation stands for (or for the abbreviation of something), not for a definition. Description questions must remain explanatory questions. It tells the model not to answer the question or add facts. Each rephrasing stays within `max_words` (20) by wording it more concisely, without dropping facts.
- **Unchanged:** approved generator `qwen3:4b` @ `359d7dd4…`, temperature 0.9, default thinking, JSON response format, six paraphrases per source, the reply parser, word limit and all rejection filters, row ID format and row schema.
- **Identity:** the corrected `generation_identity` is the length-guard identity with `prompt_extensions` replaced by `trec_answer_type` (version, decision, label definitions, `max_words`, template and selector source hashes, `carry_forward: none`). The fingerprint therefore differs from both earlier TREC identities, and no earlier row is carried forward: resume and `--verify` reject any row with an older fingerprint.
- **Historical evidence:** the pre-correction artifact remains readable with `--verify --historical`, which uses the superseded identities and reports `corrected_output: false`. Plain `--verify` refuses it with a "superseded" message.
- **Safe replacement:** generate into the isolated candidate path `synthetic/trec/candidates/auggpt-trec-answer-type-v1/auggpt_seed13.jsonl` (`--candidate`). Real in-place TREC seed-13 generation is refused. Promotion (`ws1_generation.promote_auggpt`) is explicit: a read-only `--plan`, then `--promote` with the candidate and original SHA-256 it printed. It preserves the original JSONL and sidecar byte-for-byte under `synthetic/trec/superseded/auggpt-trec-answer-type-v1/`, writes `auggpt_seed13.promotion.json` with every hash, and atomically installs the candidate's exact bytes. `--verify-promotion` re-checks everything read-only.
- **Active-path verification fails closed:** plain `--verify` accepts corrected output at the active path only together with a complete promotion record (`generate.check_promotion_record`, which `promote_auggpt.verify_promotion` also uses). The record must be schema-valid with `status: complete` and must name this task, repetition, mode, correction and decision. Its active, preserved-original and retained-candidate JSONL/sidecar hashes must all match the files on disk. So a copied candidate, an `in_progress` or malformed record, tampered hashes, or a missing or modified original or candidate all fail. `--candidate --verify` needs no record, and `--verify --historical` still reads the preserved original.
- **Downstream:** C5b and the #11 review read the active path, so after promotion they read the corrected rows. `verify_auggpt` reports the artifact and sidecar SHA-256, `prompt_correction`, `corrected_output` and the promotion record. Row IDs keep their format (preserved by lead direction), so a corrected row can share an ID with a superseded row. Evidence must therefore bind rows by artifact hash, generation fingerprint, row ID and text hash together.

## Consequences

The round-1 `trec/auggpt` judgments remain bound to the preserved original (`4711ebe6…`). After promotion, #11 must record a fresh round against the promoted artifact. The round-2 prior-ID exclusion is unchanged, so round 2 randomly samples 10 IDs different from round 1. Separately, the lead directed a targeted re-check of the two known erroneous IDs, preferably all 10 round-1 IDs, in their corrected form. That re-check stays outside the random-10 denominator. Fake-model tests show routing, identity, isolation, resume and preservation only. Whether real paraphrases keep their answer type is a question for that review. Other #11 findings (Emotion targeted distortions, ambiguity flags) are not addressed here.
